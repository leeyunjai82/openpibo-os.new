# tools/pibrain — 파이브레인 체험(Tools) 화면

파이브레인에서 `tools` 서비스가 띄우는 앱이다. `tools/launch.py` 가 보드를 보고 고른다.

    파이보     tools/          socket.io,  :50000
    파이브레인 tools/pibrain/  REST + SSE, :50000   ← 이 폴더

## 왜 하나로 안 합쳤나

**하드웨어가 다르다.** 화면이 같을 수가 없다.

| | 파이보 | 파이브레인 |
|---|---|---|
| 탭 | 장치 / 모션 / 비전 / 음성 / 시뮬 | 버튼 / LED / 카메라·비전 / 음성합성 / LCD |
| 다리 | 12축 서보 | 없음 |
| MCU | 있음 (배터리·터치·PIR) | 없음 |
| 입력 | — | 버튼 4개 |
| 화면 | OLED | LCD |

파이브레인에 파이보 화면을 띄우면 "모션" 탭 전체가 죽은 화면이 된다.
서보에 명령을 보내 놓고 아무 일도 안 일어나는 것을, 아이는 고장으로 읽는다.

전송 방식도 다시 짠 것이라(socket.io ↔ REST+SSE) 한쪽으로 맞추는 건
상수를 옮기는 일이 아니라 다시 쓰는 일이다. 지금 억지로 섞지 않는다.

`docs/plan/00-decisions.md` 1.4 에서는 "지금 병합하지 않는다"까지만 정했고,
그때는 이 폴더가 실행되지 않는 보존본이었다. 파이브레인에 파이보 화면이 뜨는 것이
실사용에서 바로 걸림돌이 되어, **병합은 그대로 미루고 선택만 붙였다.**

## 셸(단일 origin) 뒤에서 도는 데 필요한 것

포트로 바로 열든 셸의 `/tools/` 로 열든 둘 다 되어야 한다. 그래서:

- 템플릿의 정적 경로는 `../static/` — 프록시가 `/tools/static/` 으로 고친다.
- `static/index.js` 맨 위의 `__u()` 가 `fetch`/`EventSource` 를 한 겹 감싸
  `window.__BASE__`(프록시가 넣어 준다)를 절대 경로 앞에 붙인다.
  호출부가 20 군데라 각각 고치는 대신 한 겹으로 잡았다.
- `<head>` 에서 iframe 인지 보고 `html.embedded` 를 붙인다.
  CSS 가 앱 헤더만 감춘다 — 언어 버튼은 `embed.js` 가 셸 상단바로 올린다.
- `static/theme.css` 는 `ide/static/theme.css` 의 **복사본**이다.
  고칠 때는 원본을 고치고 복사할 것 — `test/run.sh` 가 4벌의 동일함을 지킨다.

## 시험

    python3 test/test_tools_launch.py     # 보드 선택 + 셸 준비 상태
    bash    test/ui/run.sh                # 브라우저로 셸 안에서 확인
